<p>接内部系统批量开号这件事，真正的难点不是「买不买独享」，而是买完之后怎么让几十个号同时在线还各跑各的。这篇是一份决策清单：先用三个问题判断要不要上独享，再按接入方式、资源配额、会话管理、合同条款四组给出勾选项，每项都写着「不满足会怎样」，能直接拿去和团队过一遍。清单过完仍然拿不准的，看最后那节止损条件。</p>

<h2>一、先回答三个问题，判断该不该上独享</h2>
<p>不是所有场景都需要独享。三个问题里有两个答「是」，独享的投入才算划算。</p>
<h3>问题一：有没有号被同段线路牵连过</h3>
<p>判断依据不是体感，是记录。翻最近两个月的异常日志，看是否出现过「A 号异常后 B 号跟着异常」，且两者出口落在同一个 /24 网段。出现过两次以上，说明池子的段分散度不够。</p>
<h3>问题二：同时在线的号是否超过五个</h3>
<p>五个以内，共享池配好环境隔离通常够用；超过五个，出口重复的概率直线上升，用一个粗略的碰撞估算：n 个号从 m 个出口里随机取，重复概率约 1-exp(-n(n-1)/2m)。20 个号配 200 个出口，重复概率已经超过 60%。</p>
<h3>问题三：单号日均任务时长是否超过两小时</h3>
<p>长任务对会话保持要求高。共享池的保持时长常见是 1–10 分钟，跑两小时以上必然中途换 IP，每换一次都可能触发重新验证。这种情况独享几乎是必选项。</p>

<h2>二、接入内部系统的四个技术选型点</h2>
<p>选型错了，后面运维成本会成倍增加。这四点在上线前必须定死。</p>
<h3>代理怎么暴露给业务</h3>
<p>两条路：业务直连代理端口，或者在内网架一层代理网关（squid、3proxy、gost 都行），业务只认网关的本地端口。号超过十个建议走网关，好处是出口切换、限流、日志都能在网关层统一做，业务代码不用改。</p>
<h3>IP 怎么拿到业务手里</h3>
<p>服务商一般给一个提取链接，返回 json 或 txt 格式的 IP:端口:账号:密码。写好定时拉取（建议 5 分钟一次），把结果落到本地表里，不要每次请求都去拉，那样既慢又容易触发提取频率限制。</p>
<h3>账号绑定与白名单</h3>
<p>在数据库里建一张 account_ip 表，字段至少包含 account_id、proxy_id、绑定时间、解绑时间、状态。绑定时做唯一约束，保证同一时刻一个出口只服务一个号。这张表是后面所有排错的基础。</p>
<p>同时把调用方公网 IP 加进服务商白名单（多数服务商支持），只允许白名单地址使用该代理。内部系统出口固定的话一定要加，能挡掉大部分凭证泄露后的盗用。</p>

<h2>四、多端同时在线的会话管理</h2>
<p>「各跑各的」听起来简单，做起来要处理三件事：谁会挤掉谁、谁在用哪条线、断了怎么续。</p>
<h3>同一账号能不能多地登录</h3>
<p>要看平台规则，不要假设可以。技术上能做的是让同一账号的所有请求都走同一个出口和同一套环境，这样即便多地操作，服务端看到的仍是同一个来源。但多端并发本身可能触碰平台限制，务必先读条款。</p>
<h3>会话粘性放在哪一层</h3>
<p>两个层次：网络层靠 sticky session 保证出口不变，应用层靠本地保存 Cookie 和登录态保证身份不变。两个都要做，只做一层会在另一层出问题，比如出口没变但 Cookie 被覆盖，表现是莫名其妙退出登录。</p>
<h3>断线之后怎么续</h3>
<p>把长任务拆成可恢复的片段，每段结束记一次断点（进度、会话标识、最后成功时间）。切换线路后从断点继续，比整段重跑省一半以上时间。这个设计要在写代码时就留好，事后补很痛苦。</p>

<h2>五、签合同前核对的五项</h2>
<h3>出口是否真独享，怎么验证</h3>
<p>要求服务商提供「同一时段该 IP 仅分配给一个客户」的书面说明，并在试用期自己做验证：连续 24 小时每 10 分钟探测一次，看延迟曲线是否出现规律性尖峰。被共享的线路在固定时段会有明显的拥塞特征。</p>
<h3>换地址的规则与地区指定</h3>
<p>独享线路也需要偶尔更换（比如原 IP 进了某些名单）。问清免费换的周期、换 IP 的生效时间（常见 10 分钟到 2 小时）、换的时候旧 IP 是否立即释放。</p>
<p>再确认地区能不能按批号统一指定。按批指定城市比按号随机分配好管理，要问清指定城市是否额外收费、同城不同运营商的段能不能挑。</p>
<h3>计费口径与故障响应</h3>
<p>按流量还是按条包月，超量怎么算，闲时流量是否另计。这几条要写进合同，别只信销售口头说的「够用」。</p>
<p>同时问清 SLA：多久响应、多久恢复、连续不可用怎么补偿。多数中小服务商给的是 4 小时响应、24 小时恢复，能做到 1 小时响应的通常价格高一档。</p>

<h2>常见问答</h2>
<h3>内部系统批量开号，用一条独享线路轮着用行不行？</h3>
<p>答：技术上能跑，但等于把共享的问题搬到自己机房——所有号同一个出口，一荣俱荣一损俱损。号超过三个就建议一号一条线，这也是「不再互相挤掉」的前提。</p>
<h3>清单过完发现只有两三项满足，还要上独享吗？</h3>
<p>答：可以先上小规模。拿三条独享线路跑最关键的几个号，其余继续用共享池，观察一个月再决定。部分迁移比全量切换风险小得多。</p>
<h3>出口池规模怎么估才不算拍脑袋？</h3>
<p>答：用碰撞概率反推。希望重复概率低于 10%，池子至少是号数的 5 倍；希望低于 3%，至少 16 倍。这个估算假设均匀分配，实际因为地区集中会更差，所以再上浮一档。</p>
<h3>多端同时在线被挤掉，是 IP 的问题还是设备的问题？</h3>
<p>答：先看是不是同环境。同一账号在两个不同 Cookie 环境里登录，服务端会认为是两台设备，后登录的通常把前面的挤掉。把环境统一、出口统一，再看是否还存在挤掉现象，才能判断是不是平台侧的并发限制。</p>
